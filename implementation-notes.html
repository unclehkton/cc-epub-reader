Decisions

  • 2026-11-10 — Every build stamps a new id into sw.js. Why: the CSP fix changed only public/_headers, so the old and new deploys shipped byte-identical sw.js (d187bac2…). An installed PWA therefore never saw a new worker and kept serving the document it cached at install, with the old connect-src. vite.config.ts now defines __BUILD_ID__ as <label>-<UTC build time>, where the label is GITHUB_SHA, the git commit, or a BUILD_ID override; the timestamp is appended even for an override, so a reused label cannot ship the same worker twice. src/sw.ts logs it, and index.html carries <meta name="build-id"> (which also changes the precache revision of the document). The existing 有新版本可用 / 重新載入 prompt stays user-driven, so a reader is never reloaded mid-book. Registration also passes updateViaCache: "none", and /sw.js is served Cache-Control: no-store because Cloudflare Pages gives .js assets max-age=14400. Rejected: automatic skipWaiting on install (would reload mid-read); network-first navigation for the document (leaves the worker stale forever, slower offline start).
  • 2026-11-10 — Cloudflare Pages connect-src must allow blob:. Why: materializeArchiveUrl size-checks the object URL with fetch(blob:). The deployed public/_headers policy said connect-src 'self', so WebKit and Chromium refused the fetch, every reveal failed closed, and the gate showed 重試. Local vite preview ignores _headers, so all e2e runs passed. Rejected: dropping the size check, or adding any remote host. blob: is local-only and does not widen network access.
  • 2026-11-10 — Parent-gate failure copy is sticky until the next click. Why: applyParentImageGateBox ran every 1s and restored idle 點擊顯示圖片, so a missing archive image looked idle after ~1s even though retry still worked. data-gate-state=error skips the idle label rewrite; the next click clears it. Visible failure text is short (失敗，重試 / compact 重試) so overflow:hidden does not clip it. Rejected: stopping the reposition timer (size/position still need it).
  • 2026-11-10 — Gate size uses CSS variables, not inline width/height. Why: .reader-host > .epub-parent-image-gate must keep !important to escape the iframe 100% sizing rule; normal inline width lost that cascade and rendered a 113×44 chip on a 278×394 plate. width: var(--gate-w) !important keeps the stylesheet in control. Rejected: more setProperty(..., "important") on inline width (fights the stylesheet). Clamp JS to iframe ∩ stage ∩ footer top so a full-plate gate cannot cover page chrome.
  • 2026-11-10 — Parent overlay hit-target is the laid-out box, including host <svg>. Why: this book’s first pages are full-bleed SVG <image xlink:href="../Images/*.jpeg"> inside a sandboxed iframe without allow-scripts. Querying only img[data-epub-src] left a blank plate with a tiny in-frame button. Setting src on SVG <image> does not paint. Rejected: auto-loading archive images (privacy gate stays); relying on in-iframe clicks (WebKit). Fixture EPUBs keep same-folder lowercase images/ HTML img.

Security / memory controls in force

  • allowScriptedContent: false + chapter CSP script-src 'none' + parent image gates.
  • replacements: "none" + pre-ready no-replacement guard (blocks archive-wide CSS blob maps).
  • Image materialize: fail-closed blob/data; one chapter-scoped in-flight promise per package path prevents duplicate extraction on rapid taps; late/stale createUrl results are disposed; size-check fail-closed; cache purged by value and path keys.
  • External links: cross-realm-safe click bridge → parent window.open(..., "noopener,noreferrer").
  • Durable IDB probe retries before session-only; share expiry uses byReceivedAt key cursor (IDB v3).
  • ZIP: declared ceilings + internalStream consumer abort (worker may still inflate — residual R1).

2026-07-22 resize and iPhone sharing follow-up

  • Window resize: resizing previously rebuilt the EPUB.js rendition through setFlow(). Several resize events could race destructive iframe rebuilds and leave the chapter blank. Resize is now coalesced by animation frame and delegates to EPUB.js rendition.resize(), preserving the active chapter, CFI, and iframe. Unit, component, and cross-breakpoint browser regressions cover this path.
  • iPhone share sheet: the manifest share target remains enabled for supporting browsers. Safari/WebKit does not implement the Web Share Target API, so a browser-only PWA cannot appear as “Books” in the iPhone share sheet. The current iPhone workflow is Save to Files, open Books, then tap 匯入 EPUB. Direct iOS share-sheet integration requires a native app with a Share Extension and is deferred beyond release 0.1.
  • Cloudflare analytics injection: the live canary detected a zone-level Cloudflare Insights script despite empty Pages analytics fields. Static responses now declare Cache-Control: public, max-age=0, must-revalidate, no-transform, preventing Cloudflare from mutating the privacy-first app HTML. A deployment-config regression requires the opt-out. The production canary at books.pkwor.com then imported and opened the fixture, retained chapter text through the resize sequence, loaded index-pBJPC5-s.js, and observed zero off-domain requests.
  • Release commits: resize fix 3063ac4; Cloudflare privacy guard a4649a7.

2026-07-25 mobile pagination overflow fix

  • Reported symptom: a supplied EPUB displayed partial lines near the beginning of the book, placed the next-page target beyond the right edge of an iPhone viewport, and surfaced EPUB.js’s No Section Found message when the reader could no longer be advanced normally.
  • Root cause: the reader shell used only implicit CSS grid columns. A long, non-wrapping book title contributed its min-content width to that implicit track, expanding the internal stage beyond the fixed viewport. In the supplied 390px Mobile Safari reproduction, the shell remained 390px while the stage grew to 696.5px and EPUB.js paginated against a 608.5px content host.
  • Fix: the reader shell now declares grid-template-columns: minmax(0, 1fr). The existing ellipsis can therefore shrink the title within the viewport, and the EPUB stage, content host, and both 44px page-edge targets stay correctly bounded.
  • Regression coverage: a repository-owned mixed fixed/reflowable EPUB fixture with a deliberately long title reproduces the overflow without retaining the user-supplied book. The mobile E2E test advances through the fixed pages into a long reflowable chapter, asserts exact 390px stage and next-edge bounds, and performs a real next-page click.
  • Verification: the supplied EPUB advanced with ordinary Mobile Safari clicks through all pages of Preface2.xhtml into Preface3.xhtml; every measured stage was 390px, the next edge stayed at x=346–390, and no alert appeared. Fresh gates: TypeScript pass; 228/228 Vitest tests; production/PWA build pass; shell 74,706 bytes gzip; audit 0 vulnerabilities; Playwright 48/48 across Chromium, WebKit, Mobile Chrome, and Mobile Safari.

2026-08-01 mobile install guidance and EPUB page-turn follow-up

  • PWA guidance: the library now shows a normal-flow paper-and-jade card directly above the licence footer only for uninstalled iPhone/iPod and Android browsers. Genuine iPhone Safari is positively identified by its Version + Mobile + Safari UA shape and explains Share → 加入主畫面; other iOS browsers and WKWebViews direct the reader to open Safari. Android uses Chrome menu guidance until beforeinstallprompt is available, then exposes 立即安裝 for the native browser prompt. A rejected native prompt keeps the browser-menu fallback visible; the close control lasts only for the current page session and no install state is stored or sent elsewhere. All copy follows the selected Traditional/Simplified Chinese UI language.
  • Installed-PWA guard: the card is absent for display-mode: standalone, display-mode: fullscreen, and iOS navigator.standalone. It deliberately does not try to programmatically open an iPhone install dialog, which Safari does not provide.
  • Swipe root cause and fix: iOS/WebKit can retain real touches inside EPUB.js’s sandboxed chapter iframe, bypassing the outer reader-stage gesture listener. Only a fixed-layout spine item explicitly marked rendition:layout-pre-paginated and containing no content controls yields its page surface to the outer reader stage. Reflowable pages and fixed pages with links, footnotes, or controls retain iframe hit testing; an iframe-bound Pointer Event fallback handles WebKit’s sandbox boundary without disabling those interactions. Parent overlays preserve WebKit-safe image gates and provide the same reliable path for safe book-internal links. Scrolled mode keeps its iframe interaction and vertical scrolling unchanged.
  • Book-edge and internal-link behavior: EPUB.js’s exact No Section Found response is treated as an idle no-op only when the current recorded spine location is already the requested book edge; it rebinds the current chapter. The same message from a mid-book navigation, and all other navigation errors, still surface normally. Parent book-internal links are resolved from the current spine first, so fragment-only footnotes and cross-directory relative chapters do not become invalid root spine requests.
  • Supplied EPUB verification: the supplied 23-spine fixed-layout/reflowable EPUB opened in Mobile Safari, its fixed-layout cover reported the package property and moved to spine item 1 via the reader-stage left-swipe path, with no No Section Found error. 2026-08-01 reader note controls and background reflow follow-up

  • EPUB link controls: sandboxed WebKit needs a parent-document click path, but individual fixed controls for every safe book-internal link stacked over the table of contents and even above the settings sheet. All EPUB-local links—including chapter, fragment, footnote, and manual-content links—now use one compact, horizontally scrollable bottom dock. The dock is mounted inside the reader host, beneath reader modals, while external links retain their 44px WebKit-safe hit targets. The same parent handler resolves each destination relative to the active spine before navigating.
  • Side-table-of-contents paths: EPUB navigation items are relative to the navigation document, not the package root expected by rendition.display(). Book summaries now normalize each TOC href against packaging.navPath (or an EPUB 2 NCX path) before the drawer receives it. This converts real paths such as ../Text/ch-02.xhtml from Text/nav.xhtml into Text/ch-02.xhtml, preventing the false No Section Found error.
  • Background reflow: background and theme changes previously updated EPUB CSS without scheduling EPUB.js’s remeasure. WebKit could therefore keep stale paginated column geometry after the settings sheet closed, and only recover on the next page turn. Every appearance change that can trigger that WebKit layout path now coalesces through the existing two-frame rendition.resize() and chapter rebind sequence.
  • Regression coverage: the unit suite proves that background/theme changes schedule exactly one relayout and that both numeric note fragments and ordinary chapter links use compact controls inside the reader host. The mobile E2E flow changes the background, closes settings, and verifies a single page column without navigation; it also opens a fixed-layout link from the bottom dock and confirms navigation to the reflowable chapter in Chromium, WebKit, Mobile Chrome, and Mobile Safari.
  • Fresh verification: npm run test:run passed 258/258; npm run check, production/PWA npm run build, and npm run check:bundle passed. The initial shell is 78,051 bytes gzip against its 153,600-byte budget. The focused fixed-layout link test passed in Chromium, WebKit, Mobile Chrome, and Mobile Safari.

2026-08-02 mobile image gate page-navigation follow-up

  • Reported symptom: on a phone, the supplied EPUB’s 點擊顯示圖片 control expanded into a dark full-page panel and covered the bottom previous/progress/next navigation bar.
  • Root cause: parent image gates are appended directly to .reader-host, so the shared direct-child rule intended for EPUB.js’s iframe applied width: 100% and height: 100% to the button. The fixed overlay consequently extended past the reader stage into the footer.
  • Fix: parent image gates now opt out of the full-size host-child rule while retaining their compact minimum touch target and fixed image-relative position. The existing iframe sizing behavior is unchanged.
  • Regression coverage: the mobile E2E flow opens the repository image-gate fixture at a 390×844 viewport and asserts the gate remains inside the reader stage and ends before the page-navigation footer. The supplied EPUB was also inspected and confirmed to use the same plain <img>-based gated-image path.
  • Verification: npm run test:run passed 259/259; npm run check, production/PWA npm run build, and npm run check:bundle passed with an initial shell of 78,046 bytes gzip against the 153,600-byte budget. The focused gate regression passed in Mobile Chrome and Mobile Safari (2/2), the full mobile suite passed in both profiles (24/24), and the cross-browser reader image-reveal flow passed in Chromium, WebKit, Mobile Chrome, and Mobile Safari (4/4).
