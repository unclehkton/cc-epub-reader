What changed

Release 0.1 is implemented on feature/release-0.1: a privacy-first Preact PWA EPUB reader with a multi-book local library, per-book CFI progress, paginated/scrolled flows, chapter-local OpenCC conversion, tap-to-load archive images, offline precache, and an installed-PWA share target that never uploads EPUB bytes to a server.

Product target URL remains https://books.pkwor.com. Hosting is static Cloudflare Pages only. This branch is a local release candidate; live deploy and domain attachment are external prerequisites.

Codex's 2026-07-22 follow-up verification confirmed several security and dependency fixes, but the full Playwright matrix failed 31/32 on the WebKit image-gate scenario. Parent overlay positioning, pre-ready EPUB.js stylesheet work, share/quota fallback, share-expiry memory use, ZIP expansion, and false-green E2E coverage remain open. Release 0.1 is not approved for deployment.

Why it changed

Readers need durable multi-book recovery on-device without accounts, analytics, or remote conversion. Single-retained-book scope was expanded to an explicit library with delete confirmation while keeping all processing in the browser.

Important decisions and trade-offs

  • Storage: EPUB payloads persist as ArrayBuffer in the bookPayload store; bookMeta holds listing fields only (IDB schema v2). ResilientLibraryRepository switches to session-only on initial open failure and on later quota/import/progress write failures.
  • Scripts: Rendition and session now use allowScriptedContent: false; package scripts are additionally blocked by chapter CSP (script-src 'none') and pre-serialization stripping.
  • Resources: Open with EPUB.js literal replacements: "none" (not falsy). Images materialize via archive.createUrl only on reveal; revoked URLs are purged from archive.urlCache.
  • Validation: Import metadata uses JSZip + container/OPF parsing. EPUB.js is lazy-loaded only for reading so the welcome shell stays under the 150 KiB gzip budget.
  • Sanitizer: Hostile active content is stripped on book.spine.hooks.content before serialization. Image sources are gated behind 點擊顯示圖片. Gates are rebound on the live chapter document after serialization so click handlers survive iframe materialization.
  • Image gates: With iframe scripts disabled, parent-document overlay controls activate chapter images. The current overlay uses iframe-local coordinates without the iframe offset and loses pair alignment after one reveal; WebKit E2E timed out waiting for the gate.
  • Playwright on Windows: Build runs before Playwright. Global setup owns a direct Vite preview process with 30-second preview/browser deadlines, while global teardown releases the exact PID. This replaces the hanging Playwright webServer hook.
  • OpenCC: Modes map to cn→t, cn→hk, cn→twp; conversion is chapter-local, never chained, generation-checked after awaits.
  • Share target: Service worker handles POST /share-target into a short-lived IndexedDB inbox and redirects to /?share-import=…. No network fallback to Pages. Inbox entries expire after 24 hours.
  • UI: Ink & Jade / Night Library; Traditional Chinese (Hong Kong) chrome; 44px targets; focus-mode fallback when Fullscreen API is unavailable.
  • Hosting: public/_headers + public/_redirects only; no Functions/Worker backend.

CSP rationale

Shipped Content-Security-Policy:

default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:; font-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'

  • connect-src 'self' — no analytics or book-data endpoints.
  • img-src blob: data: — archive object URLs after explicit reveal; no remote image fetch for gated content.
  • No frame-src/script-src blob: — default EPUB.js view path is srcdoc-class, not broad blob document scripting.
  • style-src 'unsafe-inline' — reader/EPUB chrome needs inline styles; remote stylesheets are stripped.

public/_redirects provides SPA GET fallback only. Share-target POST is SW-only and must not be described as a server upload handler.
